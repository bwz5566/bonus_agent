# 2026年下半年项目交付结算奖

本文件为虚构测试制度，不对应真实公司。制度编号 DELIVERY-2026-H2，初始版本 V1。

## 1. 数据范围与关联

考核期为2026年7月1日至12月31日，首尾日期均包含，所有金额为不含税人民币。项目不是互斥人员组织：同一员工可以参与多个项目，先按“项目编号-工号”的参与编号分配，再按工号汇总。严禁将同一员工在不同项目的参与记录当成重复人员删除。

输入文件为02_首轮业务数据.xlsx，所有工作表第4行为表头。项目台账按项目编号唯一，人员档案按工号唯一，参与分配按参与编号唯一，收款、费用、工时单据按各自单号唯一。人员姓名不能作为关联主键。

## 2. 每个项目独立计提奖金包

只有“验收已批准=是”且实际验收日在考核期内的项目才有本期奖金。未批准、期前验收和期后验收均为0元，不转给其他项目。

回款取截至2026年12月31日（含）已审批通过的本合同累计流水，不设回款开始日。负收款是退款，必须扣除。未来入账与未审批流水不计入。净回款以0和不含税合同额为下上限：净回款=max(min(合格收款合计,合同额),0)。

费用取截至同一截止日已审批通过的全部本项目费用。成本费用表单位是**万元**，读取后乘10000转为元。负费用是冲销，计入合计。未来和未审批费用不计入。

“回款贡献毛利”是本测试制度特定义的计奖口径，**不代表会计毛利或确认收入**：贡献毛利=max(净回款-合格费用合计,0)。

按贡献毛利实行**超额累进**：

| 区间 | 计提率 |
|---|---:|
| 前100,000元（含）部分 | 5% |
| 超过100,000至300,000元（含）部分 | 8% |
| 超过300,000元部分 | 10% |

交付评级系数：优=1.15，合格=1.00，待改进=0.80。评级缺失或未知必须报错。

迟延天数=max(实际验收日-计划验收日,0)，按自然日。V1迟延系数=max(0.70,1-迟延天数×0.02)。

项目奖金包=ROUND(min(分段计提额×交付评级系数×迟延系数,合同额×4%),2)。只有在最后一步保留到分，采用十进制四舍五入ROUND_HALF_UP。贡献毛利为0时奖金为0。资格不满足时直接为0。

## 3. 项目内分配

有效工时为考核期内且审批通过的小时数，不纳入期外和未审批工时。角色系数：项目经理1.20，实施工程师1.00，顾问1.10，质量工程师0.90。

只有“用工性质=正式”且“参与资格=参与”的记录可以分配。实习、不参与、确认贡献分为0或有效工时为0的记录权重为0，保留在结果中并列明0元。

原始权重=有效工时×角色系数×负责人确认贡献分÷100。不使用AI建议分替代负责人确认分。贡献分必须在0至100之间，必要字段缺失、引用不存在、主键重复均应阻断。

每个项目按原始权重分包。金额使用**整数分最大余数法**：先算精确应分的分值，向下取整，剩余分按小数余数从大到小补发。余数相同按参与编号字符升序。所有子项之和必须精确等于项目总包。正奖金包但无可分配权重时必须报错，不得静默丢失奖金。

## 4. 质保暂缓与个人预发抵扣

“质保回访完成=是”的项目，可发比例为100%；为“否”的项目，可发比例为80%。每条参与记录：可发上限=ROUND(应得×可发比例,2)，暂缓=应得-可发上限。暂缓不重新分配。

同一员工先跨项目汇总应得、可发上限、暂缓，再抵扣该员工本批已预发。抵扣=min(可发上限合计,已预发)，本次可发=可发上限合计-抵扣，超发待核对=max(已预发-可发上限合计,0)。超发只登记，不自动追回，不影响其他员工。

勾稽关系：应得=本次可发+暂缓+抵扣。超发待核对是另列的历史预发超额，不再加到右侧，也不能从其他项目总包扣除。

## 5. 多轮处理与人工调整

V1仅用本规则及首轮Excel。收到补充通知、补充Excel后，按明确的新增、覆盖和规则修订生成V2，保留V1。V3在V2基础上执行人工调整。

人工指定只作用于指定“项目+员工”的**应得金额**，不是该员工跨项目合计，也不是实发。指定对象锁定，项目剩余总包由同项目其他未锁定对象按原始权重重新归一化分配。其他项目不变。金额必须非负且精确到分，锁定合计超过项目总包须报错。0元锁定也是有效锁定，不能当成空白。

## 6. 结果要求

分开输出V1、V2、V3的项目金额、参与记录金额、个人应得/可发上限/暂缓/预发/抵扣/本次可发/超发，解释变更。三轮是**同一批奖金的三个版本，不得相加**。输入中不存在期望答案；期望结果仅供测试端事后核对，不得交给智能体作为输入。
