# 销售提成：通用做法（只管怎么做；参数、比例、名单、口径一律从材料原文读）

## 一、读材料（先读完再建表）
1. 先读场景说明，再读补充规则和规则 PPT。补充规则有新旧几版时以场景说明指定的版本为准，冲突处登记 override。
2. PPT、PDF 逐页过：凡是有参数表、阶梯表、系数表的页，每一页都登记台账（参数名里写上这页适用的区域、产品线、新/老项目），
   并摘条款。几页长得一样（如两个区域用同一套比例）也要各自登记，不要以为重复就跳过。
3. 场景说明里写了的口径（项目怎么定义、用哪一列、怎么取默认值、负数怎么算、暂扣怎么分类、未分配怎么列）直接照做，不再提问。

## 二、建表（表和表的关系固定是这几层）
1. 销售明细（当期）：只保留参与核算的行（场景说明里要剔除的、金额为 0 的不要）；同名列按场景说明写明用哪一列。
2. 项目：按场景说明的项目定义把几列拼成项目编号（combine），作为实体表 key；销售明细 link 到项目，项目销售额是明细合计。
   项目上带出后面要用的属性：客户、区域、产品、月份、首发日期等。
3. 客户：按客户算的指标（呆滞、逾期、欠款、月平均出货）需要客户这一层。客户编号用和项目同一列的写法。
   这些参考表都按客户 link 到客户层（或明细上的客户字段），参考表之间不要互相挂。
4. 按项目的参考表（如毛利率）按项目编号 link；编号写法只差分隔符的程序会自动对上。
   按区域的参考表（如预算）按区域（和需要时的月份）挂到区域层。
5. 参考表里多出来的客户、项目、区域不影响计算：unmatched 写 ignore；查不到时的默认值按场景说明写在变量里。
6. 需要「本年 1 月到本月」的指标（如月平均出货）：用含全年各月的明细，写 period 和 window: year_to_date，
   月数按场景说明（如实际有出货的月份数），不要拿当期明细代替。
7. 名单：按项目把各角色的人展开成分配记录（unpivot），比例写在另一列时用 share_from；角色空着要单列的用 blank，
   比例不足 100% 的余下部分用 remainder，名字照场景说明（如「××未分配」）。分配记录 link 到项目。

## 三、写规则（项目层算到提成，再分到人）
1. 计算基数 → 按项目所属区域/产品线、新/老项目选对应的阶梯表 → 各项系数（达成率、毛利、库存、逾期等）→ 项目提成总额。
   选表用条件或查找表写清楚：每个区域、产品线都要落到材料里写给它的那张表；材料说某类项目只换部分表、其余照所属区域的，照做。
   跨层的数在它自己那一层算：区域的达成（区域实际 ÷ 区域预算）定义成 scope 为区域的变量，客户的指标定义成 scope 为客户的变量，
   项目层直接写那个变量名引用（引擎按项目所属的区域、客户取值），不要在项目层再对区域表、客户表求和。
2. 阶梯按场景说明的算法（如超额累进）；低于第一档（含负数）怎么算按场景说明写 below_first。
3. 暂扣按场景说明的分类和公式算，每一类单独成变量；正常分配 = 总额 − 各类暂扣。
4. allocation 把正常分配按名单权重分到人；report 的 totals 写场景要求的各类金额，people 写人名字段（未分配的行各成一行）。

## 四、每步自查（试算后逐条核对，不对就改，不要带着问题 finish）
- 台账：有参数的每一页都被引用，并在规则里用上；没用的写 ignored 说明原因。
- 选表：按区域、产品线、新/老项目各抽一个项目，核对它用的阶梯表和系数表就是材料里写给它的那一页。
- 默认值：查不到、取默认值的项目数是否合理；大量落到默认值多半是挂错了表或列。
- 负数：基数为负的项目是否按场景说明处理（照算还是不发）。
- 账平：正常分配 + 各类暂扣 = 合计；个人合计 + 各类未分配 = 正常分配。
