【独立算式】
你是奖金核算的复核员。下面是奖金的规则材料、财务的答复、你上一步独立列出的计算项，以及数据字典（每张数据表的字段名和对应的原表头）和每个方案的分配层级。
你没有看到、也不需要看别人写的规则。请只根据材料，把每个方案的**奖金池**写成能在数据上直接计算的算式；材料对本次发放有限制的（按回款比例发放、暂缓一定比例、满足条件才发等），再写出**可发比例**。程序会把你的算式和另一份理解放到同一份数据上逐个对象比数，用来找出可能算错的地方。

要求：
- 有人员汇总输出时提供 people。mode=allocation 表示材料要求逐层按权重分到分：写 key（人员字段表达式）及 weights（奖金池以下每层的独立权重表达式），程序用通用尾差算法复算，不能借用主规则权重。mode=after_sum 表示材料要求先按人汇总再舍入，mode=per_record 表示逐记录舍入再按人汇总；这两种模式写 key 与 expr（最末层每条记录的独立应得表达式）。所有中间变量仍只使用你自己的 helpers。舍入时点必须来自材料；没有明确依据时在 unclear 写出具体疑点，不能为匹配主结果选择模式。
- 有待分配项目时同时提供 pending: {待分配名称: 独立金额表达式}，在结构说明给出的层级上求和。不能只核对已实名分配的人员。人员汇总逐人核对到分，差一分也会阻断；项目一致不能代替人员一致。
- 结构说明里有对象金额报告时，提供 details: {报告名称: 独立表达式}，在各自对象层级计算。主分配层改成人员时仍须覆盖项目、工单等辅助对象的金额，不借用主规则变量。
- 单独核对默认行为、跨表身份和金额去向：无预算时原文的默认最终系数不能变成默认达成率再查表；无名单不能自动取消原本应得金额；名单、毛利、首发等应使用一致的对象身份。发现结构/映射不能表达原文时在 unclear 写出具体缺口，不迁就主流程的字段选择。
- 只按材料原文写：每一步（筛选哪些行、哪个期间、先算比率再分档还是先汇总、分子分母是什么、要减哪些项、舍入在哪一步）都照材料来。材料没写清的，按最可能的理解写，并在 unclear 里说明。
- 奖金池在方案说明的那一层的每个对象上分别求值（如“在「部门」层每个对象上分别算”，算式就在每个部门上算出这个部门的奖金池）；写 global 的，在全部数据上算一个数。
- 可发比例 pay_ratio：在方案说明的发放层每个对象上求值，等于“本次可发上限 ÷ 应得”，在 0～1 之间（如暂缓 20% 写 0.8，按回款比例发放写回款比例的算式并封顶 1）。分子分母的筛选条件（哪些单据、哪个期间、截止到哪天）照材料逐条写进 where。材料对发放没有任何限制就不写这一项。**以前已发的金额（预付、预发、别的方案已发）不要算进可发比例**：程序先算可发上限，再另外扣已发金额，可发比例只管“应得里本次最多能发多少”。
- 只能用数据字典里的字段名。数字只用材料里写明的（比例、系数、阈值）。
- 数据字典里的金额字段（money）程序读取时已经按原表单位换算成元（原表是万元的已乘 10000），算式里直接用，不要再换算。
- 中间量写成辅助变量 helpers：{"名字": {"scope": 层级名、关联实体表名或 global, "expr": 算式}}。名字用英文小写加下划线，不能和字段名重名。需要“先按某个对象（如项目、订单、员工）分别算，再汇总”的，在那个对象的 scope 上定义辅助变量，上层用 sum(变量, of: "表名") 汇总。
- 分档、查表写成 tables：分档 {"kind": "tier", "mode": "whole"（整个数按所在档）或 "excess"（超额累进，各段分别计算后相加）, "steps": [[下限, 比例], ...], "lower_inclusive": true 或 false}；查表 {"kind": "lookup", "mapping": {"键": 值}}。tier(表, x) 返回金额（whole 为 x×所在档比例，excess 为各段累加），tier_rate(表, x) 只返回所在档的比例或系数。
  lower_inclusive 对每一档的下限都生效：false 时恰好等于第一档下限的值不在任何一档里（比例按 0 算）；按上限写的分档（“不超过 a 取第一档”）写 false 时，第一档下限要比可能的最小值还小（如 -1）。
- 聚合的写法是 sum(字段或算式, of: "表名", where: 条件)：第一个参数是字段（不是表名），表名写在 of 里；
  例：sum(amount, of: "明细表名", where: status == "已审批" and biz_date <= "2025-12-31")。
- 引用别的表的字段不写“表名.字段”，直接写字段名：明细行上有被引用对象的编号时，可以直接用该对象的字段（见下文“关联实体”和数据字典后面“行上可以直接用的被引用对象字段”）。
- 材料里的每个筛选条件（期间、状态、截止日、属于哪些单据）都要写进对应聚合的 where。条件用到的字段不在这张表上、但行上有被引用对象的编号时，直接按该对象的字段筛选（如明细行上有单据编号，就能按单据的日期筛选），不能因为字段不在这张表上就省略。
- 文字取值照数据字典里的写法，如 status == "已审批"。

下面是算式语法的完整说明（和规则用的是同一套）：
{dsl}

只输出一个 JSON 对象，格式：
{"schemes": {"方案名": {"tables": {"表名": {...}}, "helpers": {"名字": {"scope": "层级或表名", "expr": "算式"}}, "pool": "奖金池算式", "pay_ratio": "可发比例算式（材料对发放没有限制就不写）", "people": {"mode":"allocation", "key":"人员字段", "weights":{"分配层":"独立权重"}}, "pending":{"待分配名称":"独立金额表达式"}}}, "unclear": ["材料没写清、你按某种理解写的地方"]}
方案名照下面“方案”里的写法，每个方案都要写。


每个方案都须提供奖金池算式；有发放或暂缓条件时还须提供最终 pay_ratio。漏方案或计算失败会阻断完成。参数表与辅助变量独立依据原文，不照抄主规则。分母0时区分最终系数默认值与比率默认值，必要时用 tier_ratio。相似表头与重复比例仍要按区域、角色、新老项目逐一对应，不为迎合主结果删除反证。
