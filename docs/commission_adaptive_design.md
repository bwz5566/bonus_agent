# 自适应提成核算链路（v2）

## 交付边界

固定的是执行顺序、来源覆盖、合同编译、独立复核、真实总额确认、逐对象确定性计算、资金去向及版本失效。项目键、数据集、指标、阈值、公式组合、人员身份、角色和人员层核算不固定为某个企业、月份或表名。

新建固定提成案卷进入 `sales_commission_v2`；已存在 v1 案卷续跑仍按其原有业务合同复算，不把旧案卷伪装成新链路验收。新链路不执行模型生成的 Python，不使用期望结果决定业务规则。

## 实际流程

1. 物理材料目录：原始工作表、表头候选、原生制度单元格、原文段落及来源指纹。文件名/关键词用于排序而非遮蔽。XLSX/XLSM、CSV/TSV、结构化 JSON 数据及 PPT/Word/PDF 原文参数支持不同物理布局；未读取的有效材料不能默认忽略。
2. 规则覆盖：按真实来源单元分段抽取义务、精确引用、责任阶段。不合并成长对话。实际公式中的每个符号绑定到计算计划；未消费的业务条款不能靠写在备注中通过验收。实际财务修订仅替代选定原文，保留其余条款。
3. 数据绑定：语义字段与多个物理来源分别映射；明确单位、空值、字段值域、数据粒度及唯一性、重复和外键关系。异构数据可合并，但不得重复导入同一物理行。
4. 项目计划：分阶段、分指标组编译结构化表达式；只传当前组原文、具名依赖、必要数据模式及真实参数表。算子包含条件、算术、聚合、按键关联、期间、阶梯和舍入。检测循环、不可表达规则、区间缺口/重叠和实际数据反例。
5. 项目核算及独立复核：所有对象用 Decimal 及有理数独立路径复算，全部资金去向闭合；指标报告证据风险而非模型主观概率。问题返回实际责任节点，合同/证据无变化时停止重复尝试。
6. 财务确认：审批绑定本版来源、项目、实际规则与金额指纹，确认前不产生正式人员结果。
7. 归属及人员层：动态角色/份额或单一直接归属；有人员计奖、预发抵扣、封顶等另建人员主集合和指标计划，以已确认项目归属关系为上游实际数据。保留零项目员工，同名按唯一编号区分。归属金额、规则调整、应得、扣减、实发及舍入尾差分别对账。
8. 输出与版本修订：按实际键、指标、角色、人员层及输出要求生成底稿和汇总。可生成等价 Excel 公式的表达式写真实公式，不支持 Excel 等价语义的表达式保留明确标记的已核验程序值及来源。逐条回读验证，财务异议登记新版本，旧批准及输出保留历史。

## 主要模块

- `bonus_agent/commission_sources.py`：真实文件、坐标、来源目录与可读性。
- `bonus_agent/adaptive_rules.py`：全来源规则清单、真实引用与明示公式结构校验。
- `bonus_agent/adaptive_sources.py`：类型、单位、来源绑定、数据粒度、关联完整性。
- `bonus_core/engine/intervals.py`：完整上下界、单位和端点校验。
- `bonus_core/engine/adaptive.py`：通用具名指标 DAG、确定性表达式、聚合、归属和人员层。
- `bonus_agent/adaptive_compiler.py`：按流程阶段及指标组编译、回执和重放。
- `bonus_agent/adaptive_export.py`：动态财务底稿、计算追溯、人员层及回读。
- `bonus_agent/commission_chain.py`：共用正式入口、检查点、复核、审批、纠错和输出。
- `bonus_agent/commission_revision.py`：原文条款修订、实际身份变更、影响范围和差异报告。

## 验收条件（不是测试数量）

| 目标 | 必须取得的证据 |
|---|---|
| 材料改名/列移动/多来源/新格式 | 物理来源能绑定，缺源或不可读不发布旧口径结果 |
| 规则新增与更新 | 漏新系数、缺档、重叠档、未映射参数、未知运算明确失败；正确新规则重算 |
| 不同业务键/指标/角色 | 不是固定五指标或五角色；任意已声明组合键、身份及实际源粒度 |
| 人员层核算 | 订单归属后可独立计算人员指标、调整、抵扣及实发，零项目人员仍保留 |
| 资金/审批闭环 | 人员前必须有本版总额确认；材料或规则变化使应受影响的审批失效；只改名单时项目合同完全一致才沿用 |
| 自我修复 | 实际反例返回责任合同；错误候选不能有通过回执；相同反例且无新证据不继续循环 |
| 旧规则兼容 | 使用原始材料复算 T34-d 冻结合同，逐项目及人员与原正式结果一致 |
| 独立批次 | 真实模型从空案卷编制独立材料，答案只在结果冻结后对账，身份、全指标及资金去向逐项一致 |

当前已建立不同业务结构、缺因子修复、版本变更、真实审批接口及报表的离线端到端测试；V5 独立原始材料的确定性订单/人员两层核算已经逐字段和本地独立答案核对。该证据不能替代真实模型冷启动验收。在线验收须使用实际授权的输入范围和实际财务/测试审批，不将已手工编制合同注入新案卷。

## 已发现的问题及诊断约定

- 规则材料首行不一定是表头。只有明确的通用结构标签可以自动归为结构说明；无表头的数字费率或文字政策仍然进入规则覆盖。
- 原文公式后的解释不能被当成算式，函数内部标点不能产生错误切分。人员汇总后的计奖或预发规则不能编入主对象层。模型提交真实业务层级和动作，程序决定责任节点。
- 对原件明确规定的全部输入表表头、数据起始行和原始金额单位，程序将其登记为可执行物理绑定断言，不允许只引用或归为背景。输入单位与输出展示单位分别处理。主对象外键的实际目标表（包括必要的人员主表）须在编制公式前完成绑定及完整性核验；这不代表提前执行人员金额。
- 同一来源、同一期间的真实历史独立模型回执可按实际原文逐条重新校验。失败一条不应导致已验证原文重新提取；错误引用、错误层级、过期规则和没有通过回执的候选不能以历史记忆直接通过。
- 两个来源绑定节点共享实际物理数据合同及关联回执，不重复导入已通过的数据表。对已证明每主对象恰有一条源记录的真实粒度，程序生成具名原始属性；模型选定并实际执行的源查询可以按原算式提升为辅助指标，不换聚合算法。无歧义的字面量包装和单月期间参数可规范化，模糊期间仍须澄清。
- 没有有效业务条款的指标阶段由程序跳过。原件明确单一直接归属、没有主对象扣减、唯一终点金额公式及依赖均可证明时，程序能够建立待确认资金合同；否则由模型选择及独立复核。原有总额确认与后续独立人员层计算不变。局部复核先用 Pro 常规模式，持续语义反例才要求深度思考；无效替换保留原候选供复核，不重启 Flash。按节点设置墙时和输出上限，已发请求超时或缺少实际用量时保留未知额度，不能自行计为零或反复发送。
- 对已经证明的单一归属及独立人员核算，归属阶段只接收真实归属规则，人员系数、预发和实发另行编制。待分配名称只在实际允许待分配时必填；编号占位不是实际姓名，后续按真实唯一身份读人员主表，并保留原始归属证据。公式中的实际字面量可由已核验等值参数表达，不把同值的不同业务符号合并。最终复核区别全体与样本，显式提供当前原文身份口径；无实际条款、对象、字段及差异的复核意见不撤销有效计算合同。
- 新案卷使用 v2 流程清单，网页、工作流文件与实际执行模式一致。失败归档同时保留责任节点、数据集、指标、对象键、实际原文/物理位置、缺少的合同或校验反例及对交付的影响。程序技术修复不应要求财务重新确认已有明确口径。

**验收状态**：离线端到端、跨结构、公式/金额、回读和旧案兼容的证据已建立。独立真实模型的编制与核算仍需走到总额确认、人员核算及独立对账，才能把该项判为通过。不得用上述离线结果推定线上自主执行已通过。
