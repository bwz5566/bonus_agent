# 子 Agent 实验模式

本分支以 e2dedda 为对照，实验入口为 `--execution-mode multi_agent`；默认仍为 `staged`。
旧案卷不能直接更换执行模式，请新建实验案卷，输入只使用原材料。参考答案不放入材料目录。

```text
bonus-agent serve --data D:\bonus_data --model deepseek-flash-pro --execution-mode multi_agent
bonus-agent auto --model deepseek-flash-pro --execution-mode multi_agent --out <新实验目录> <原材料目录>
bonus-agent agent-compare <单Agent输出目录> <多Agent输出目录> --out <对照报告.json>
```

一个服务实例统一执行模式；对照服务请使用另一端口。启动实验服务不会自动迁移旧案卷。
真实模型运行需要另行恢复在线验证；实现及离线测试不证明自动业务核算已通过。

## 处理方式

主协调角色完成材料盘点和任务规划；规则、数据、公式和终检分别保存独立历史。
公式任务最多两个并行提出工具动作，程序按当前任务版本及权限串行提交。
工具在隔离工作区执行，异常和部分登记不会覆盖原工作区。程序检查报告、独立基线和复核尝试次数保留；局部失败不会抹去反例。
金额预核算、总额复核和分配入口由调度器按阶段直接调用，避免模型反复决定是否执行确定的下一步。
总额复核仍以独立原文会话重建公式；总额人工确认、最终复核和导出门禁不变。

角色工具权限在程序层检查，公式写入只限其目标及绑定。范围错误、错页、单位、阶梯模式和负数政策继续由现有检查负责。
单次模型响应允许1—4个当前角色可用的工具调用，校验后串行逐项提交；前一动作改变本任务后，后续动作仍检查当前权限和版本。其他任务或公共口径变化会拒绝旧候选。
空响应、越权调用、超出批量上限及错误参数保存响应摘录和请求元数据，最多纠正一次。纠正也消耗累计预算；两次无效响应后暂停，重启不为同版本重新发放协议预算。
部分登记整批回滚，反馈显式标记ROLLED_BACK，隔离草稿的登记数量不当作实际已保存数量。
角色需要修正公共证据或数据时，用request_module_repair转派rules/data/coordinator并保存原任务；修复角色完成实质修改后finish_module_repair返回原任务重新检查。仅改笔记或反思不能完成修复，数据修复还须通过prepare_data；修复链禁止返回已访问角色，预算和案卷记录跨轮保留。
过期候选返回STALE并重新调度，不计业务纠错失败、不发放通过回执；无关参数登记不丢弃其他模块的候选，整案编译仍检查全部未绑定参数。
分配、报表等大组件用patch_rule_component按子路径分块编辑，保留其他字段，最终仍须完整构件检查和编译。

独立总额复核除公式外还须返回原文业务要求清单、全部规则来源、逐数据集主键/关联/期间窗口契约。来源、算式目标、条款覆盖或数据粒度不一致时，即使金额相同也不能通过。
人员、实发和抵扣条款延期到分配后的全量独立复核，不强塞进奖金池；未完成当前版本全量复核不能finish。
独立复核输出预留按条款和数据集规模控制在8192—32768 Token，思考输出也计入预留；服务端截断仍保持阻断，不把半份JSON当结果。

同一个 Key 供所有模型调用使用；每个请求的模型对象、思考内容及用量私有，统一汇总。
当前采用进程内全局两个请求槽；多进程部署不共享此限流器。
总预算沿用 `--max-tokens`，实验模式按案卷累计，正常跨轮恢复不重置。
每次调用预留估算输入及最大输出；服务实际用量可能偏离估算，预算并非精确账单。
每批候选返回和每次工具处理后保存案卷检查点。进程在请求中崩溃时，服务端已经发生但尚未返回的用量无法从本地恢复，需核对服务账单。
运行时间累计上限1800秒。停止后不再启动新请求，已发送请求等待返回并计费。
同问题两次失败后允许一次配置的独立顾问诊断，随后阻塞；上下文或接口错误直接保存现场。
重要金额模块在工作模型上开启思考；必要独立复核使用原checker配置，不静默降级。

## 验证及结论

先验证权限、依赖、过期提交、事务回滚、部分登记、预算及恢复；之后才进行真实自动流程对照。
两种模式使用相同输入、期间、财务口径、模型、复核配置和总预算。每组至少两次独立运行才讨论稳定性，费用单独参考服务账单。
逐项目、人员、待分配、暂扣、舍入差额和导出全部验收，不能只比较总金额。
真实输入和业务政策必须能更换，不添加客户、月份、金额或角色比例的案例默认值。

对照命令只读取案卷，不调用模型。缺少条件记录时标记不可比；相同输出不证明业务正确。
离线测试只能说明机制，人工修复副本只能说明该副本；二者都不能代替自动模型验收。

现阶段限制：规则和数据阶段各由单个职责角色处理；只并行无依赖的公式候选，尚不缓存逐变量金额。
子任务记录的PASS只代表局部程序检查。业务日期、匹配及舍入口径不明确时必须保留草稿。
